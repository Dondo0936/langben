1. One-page pitch

Langfuse shows messages.create. A Vietnamese production bot shows:

Zalo user → OA webhook → FPT.AI / Viettel NLP → LLM → TTS → reply on Zalo

If we only copy Langfuse, that path is invisible. Vết is LLM observability and channel observability.

Pitch: Langfuse for Vietnamese production bots — trace the Zalo / FPT / Viettel / .NET path, not only the LLM call.

LayerJob
A. CoreProjects, traces, sessions, scores, prompts, playground, evals, usage dashboard — Langfuse-shaped.
B. RoutesZalo OA/Bot, FPT.AI Conversation, Viettel ASR/TTS/NLP, Lark, Google Chat, .NET/Teams inbound.

A without B is a weaker Langfuse. B without A is a webhook logger. Both are required.

3. Goals, non-goals, parked ideas

Goals

  • A developer can open a Zalo user session and see inbound message, NLU, LLM, tools, TTS, outbound reply as one tree.
  • A developer can wrap Anthropic (and OpenAI-compat / FPT Factory) and see Langfuse-style generations.
  • A .NET bot can emit OTLP and land in the same UI.
  • Empty, loading, and error states exist in Vietnamese.
  • The product does not claim to be Langfuse.

Non-goals (v1)

  • Langfuse Cloud parity (annotation queues at their depth, prompt experiments at scale, 20 judge templates).
  • ClickHouse as day-one store.
  • Using Langfuse ee/ features (SCIM, their custom-logo Cloud path, etc.).
  • Viettel Cyberbot as a public webhook (enterprise / sales API — SDK spans only until a spec exists).
  • Zalo/FPT as “Playground model dropdowns” only — they are channels, not just LLM connections.
  • Facebook Messenger / Viber / Telegram in v1 (same adapter interface later).

Parked

  • Claude-for-Excel pipeline-point eval kit.
  • Standalone “usage report SaaS” — the turn receipt in session detail covers this.

8. Part B — Vietnamese routes & channels

Each connector: verify → normalize to a turn → optional forward. Same span names everywhere.

SpanMeaning
channel.inboundUser message from Zalo / Lark / Chat / Bot Framework
nluFPT intent, Viettel NER/segment/spell
generationClaude, FPT Factory, vLLM, etc.
toolCRM, search, booking
speech.asr / speech.ttsViettel STT/TTS
channel.outboundBot reply on the same channel

Session = (channel, user_id) e.g. zalo:oa_123:user_456.
Route = named pipeline e.g. zalo-oa → fpt-conversation → claude → zalo-reply.

8.1 Zalo (ship first)

Two official surfaces:

  • Official Account: POST webhook, X-ZEvent-Signature = sha256(appId + data + timestamp + OA secret). Events: user_send_text/image/file/…, oa_send_*, follow/unfollow, GMF groups.
  • Zalo Bot: X-Bot-Api-Secret-Token, message.text.received, etc.

Endpoint: POST /hooks/zalo/{oa|bot}/{projectId}

  1. Verify MAC / token.
  2. Emit channel.inbound.
  3. Optional forward to customer bot URL (transparent tap) with timeout and kill switch.
  4. Match oa_send_* as channel.outbound via msg_id / quote_msg_id.

This is the default VN CX path.

8.2 FPT.AI Conversation / Agents

  • Send to bot: POST https://bot.fpt.ai/api/get_answer/ (channel, app_code, sender_id, message).
  • Bot replies to your webhook (BotManager.parse_response).
  • FPT Agents also send channel + broker_id (Zalo OA id, Facebook Page, Teams, …).

Wrap get_answer and/or ingest the response webhook so one trace is: user text → FPT DME → reply payloads (buttons, carousel). Tag route=fpt-conversation; nest channel=zalo when FPT is only the brain.

FPT AI Factory (mkp-api.fptcloud.com/v1) is a generation provider, not a channel.

8.3 Viettel AI

Public APIs are speech + NLP, not a Zalo-style chat webhook:

  • ASR …/voice/api/asr/v1/rest/decode_file (+ WebSocket streaming)
  • TTS …/voice/api/tts/v1/rest/syn
  • NLP: spell-check, NER, POS, segment on viettelgroup.ai/nlp/api/v1/…

SDK wrappers: each call is speech.asr, speech.tts, nlu.* with duration, voice id. Cyberbot/callbot: no self-serve webhook in this plan — instrument inside the customer’s adapter via .NET/Python.

Langfuse has no ASR/TTS observation type. Add it.

8.4 Lark / Feishu

  • Event im.message.receive_v1.
  • Webhook (challenge + optional encrypt) or SDK WebSocket long-connection.

POST /hooks/lark/{projectId} — echo challenge, decrypt if configured. Domain switch: Lark vs Feishu. Normalize to the same turn schema.

8.5 Google Chat

Google Workspace Chat apps: HTTP endpoint, event payload, verification. Space/DM + thread id → session. Do not confuse with Gemini (generation provider).

POST /hooks/google-chat/{projectId}

8.6 .NET inbound

Not a messenger. C# / ASP.NET is the default at many FPT / Viettel / bank shops. Langfuse is Python/JS-first; that is a hole.

Ship:

  • NuGet tracer: ActivitySource → OTLP to Vết.
  • ASP.NET middleware: start a turn on HTTP POST (Bot Framework activity or forwarded Zalo webhook).
  • Map Microsoft 365 Agents / Teams SDK spans (agents.adapter.process, turn metrics) into our tree.
  • Optional channel tag msteams.

8.7 Later, same adapter interface

Facebook Messenger, Instagram, Livechat, Viber, Telegram. Do not block v1.

VietAPI and similar gateways: document as OpenAI/Anthropic-compat generation presets, labeled as gateways, not labs.

9. Canonical data model

Project
  id, name, publicKey, secretKeyHash

ChannelConfig
  projectId, type (zalo_oa | zalo_bot | fpt | viettel | lark | gchat | custom)
  secrets (encrypted), webhookPath, forwardUrl, enabled

Route
  projectId, name, steps[]  // display + filtering

Trace
  id, projectId, name, sessionId, userId
  channel, routeId, release, environment, tags[]
  start, end, status, metadata

Observation  (span)
  id, traceId, parentId, type
    generation | span | tool | channel.inbound | channel.outbound
    | nlu | speech.asr | speech.tts
  name, start, end, status, input, output, model, usage, metadata

Session
  id, projectId, channel, userId, firstSeen, lastSeen

Score
  traceId or observationId, name, value, comment, source (manual|eval)

Prompt
  projectId, name, version, messages[], config

Usage on generations: input_tokens, output_tokens, cache read/create, estimated cost (labeled ước tính). Viettel spans: audio ms, voice id, not token USD unless the user sets a rate card.

Store payloads as JSON (redact PII fields by config). Optional object store for ASR audio — off by default.

10. Ingest modes

Mode 1 — Tap (zero bot rewrite)
  Zalo ──webhook──► Vết ──forward──► customer bot
                       │
                       └── trace inbound / outbound

Mode 2 — SDK (in-process)
  wrapAnthropic / wrapOpenAI / wrapFptGetAnswer / wrapViettelTts
  → POST /api/ingest  or  OTLP

Mode 3 — OTLP
  .NET / Teams SDK / any OTel → /otlp/v1/traces

Zalo / Lark / Google Chat: Mode 1 first. FPT / Viettel / Anthropic: Mode 2. .NET: Mode 2 + 3.

Forwarding is a production liability (latency, dual delivery, secrets). v1: timeout, retries=0 or 1, kill switch, log forward failures as spans. SDK path is the reliable default once the bot can add a package.

14. Security & PII

  • Zalo/Lark payloads contain names, user ids, sometimes phones. Default: store; settings: redact keys matching phone, email, address.
  • Webhook secrets encrypted at rest. Hook URLs are unguessable (projectId + random suffix).
  • Do not log raw OA secret. Do not forward to a third-party Langfuse Cloud.
  • Audio (Viettel ASR): opt-in retention; default drop binary after transcription span is written.
  • Playground keys stay server-side.

16. Acceptance checks

Core is done when:

  • Sidebar + traces list + trace detail work in Vietnamese on desktop and a narrow viewport.
  • Ingest creates a visible trace without restarting the server.
  • Seeded Zalo-shaped turn shows inbound + generation + outbound.
  • Anthropic wrap records model, tokens, latency when a key is present; degrades cleanly when not.

Channel layer is done when:

  • A signed fixture POST to /hooks/zalo/oa/... appears as a session, not only a raw log line.
  • Invalid signature is 401 and does not create a turn.
  • Forward can be turned off without breaking ingest.

18. Appendix — connector notes

Zalo OA signature

mac = sha256(appId + data + timeStamp + OAsecretKey) with data the JSON body string as documented. Prefer X-ZEvent-Timestamp when present. 7-day CS message window is a Zalo product limit, not ours — document it.

FPT get_answer

channel is often "api" for custom integrations; production OA traffic may already be connected inside FPT’s console. We still want the response webhook so replies are traced even when FPT owns the Zalo pipe.

Viettel TTS example fields

text, voice, speed, tts_return_option (stream / wav / mp3). Span output: duration, format, not the full audio blob by default.

Lark challenge

Return { "challenge": "<value>" } within 1s on URL verification. Encrypted events need the encrypt key from the developer console.

Google Chat

Verify per Google Chat app docs (audience / bearer). Map space.name + user to session id.

Langfuse UI files to study if vendoring

  • Sidebar / nav (collapsible, project switcher)
  • Traces table + filter rail
  • trace2 layout: tree, timeline, I/O, mobile tabs
  • Playground

Do not vendor worker, ClickHouse migrations, or ee/.
